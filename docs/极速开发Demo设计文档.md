# 【Demo设计文档】PURGE_PROTOCOL.EXE

## 一、 操作规则

本 Demo 采用键鼠操作，具体功能映射如下：

| 操作按键           | 功能描述           | 详细说明                                                     |
| :----------------- | :----------------- | :----------------------------------------------------------- |
| **WASD**           | 移动               | 控制角色在地面进行基础位移。                                 |
| **鼠标**           | 视角调整           | 第三人称视角控制。                                           |
| **空格 (Space)**   | 跳跃 / 二段跳      | 支持空中二次起跳，用于跨越地形或躲避攻击。                   |
| **Shift/鼠标右键** | 冲刺               | 仅限地面使用的快速位移，用于走位。                           |
| **E 键**           | 传递（机关，轻击） | 消耗 1 格能量，激活攻击机关（触发后机关会进入冷却）。        |
| **F 键**           | 传递（机关，重击） | 消耗 3 格能量，激活攻击机关释放更大的炮弹，命中 Boss 触发其【瘫痪】。 |
| **鼠标左键**       | 处决/攻击          | 近距离面对瘫痪状态下的 Boss 时触发；二阶段瞄准状态下发射激光。 |
| **Q 键**           | 战术瞄准           | （二阶段解锁）开启全局 0.2x 减速与屏幕灰色滤镜，进入子弹时间。 |
| **P 键**           | 暂停菜单           | 呼出系统菜单，解除鼠标锁定。                                 |

## 二、 背景设定与攻略

### 2.1 背景设定

玩家扮演系统底层的“清理程序”（蓝色），对抗入侵的“核心病毒”（红色）。“传递”代表着玩家收集能量传递到攻击机关，攻击机关再传递给 Boss，玩家的Q技能则传递能量直接给 Boss，玩家的处决则作为奖励机制。当病毒血量降至 50% 时，病毒将更加疯狂，双方进行最终决战。

### 2.2 核心通关攻略

本 Demo 的战斗分为一阶段与二阶段，核心逻辑围绕“能量传递”展开：

- **一阶段：**
  - **玩法**：玩家身处平台 A，Boss 位于平台 B。玩家需通过走位躲避 Boss 的红圈落石与多线冲刺，能量球 6.5 秒限时内未拾取则消失，需要玩家抓紧时间拾取能量球。
  - **博弈**：攒满 3 格能量后，玩家靠近攻击机关并且按 F 传递，攻击机关会发射更强的炮弹造成更高的伤害并使 Boss 瘫痪。此时场地中央会生成平台 C，玩家可以选择通过 A→C→B 跳跃至 Boss 处进行左键处决（处决会额外爆出 1 个能量球）。或者继续在平台 A 收集能量球，但 Boss 瘫痪时间只会持续 15 秒，玩家若选择处决则需尽快返回 A 平台，否则会被苏醒的 Boss 释放推力技能击飞回 A 平台并受到伤害。
  - **攻略**：在安全的情况下，尽可能多的收集到3格能量，发射炮弹致使 Boss 瘫痪后进行处决；也可以使用1格能量发射威力略小的炮弹进行攻击。
- **二阶段：**
  - **玩法**：Boss 血量降至 50% 时会播放转阶段动画，跳跃高空并将玩家击飞，会有很小的伤害。玩家能量上限会被扩展至 5 格，Boss 攻击频率也将大幅提升（间隔从 5 秒缩短至 3 秒）。
  - **输出**：玩家需要选择是继续冒险近战处决 Boss，还是攒满 5 格能量后，按下 Q 键进入子弹时间，瞄准 Boss 按左键释放高能激光。
  - **攻略**：在安全的情况下，尽可能多的收集到 5 格能量释放高能激光；也可以继续采用“3格能量瘫痪+处决”的循环，两种输出路线的总伤害差距不大。

## 三、 设计思路

- **关于“传递”**：
  - 在拿到这个主题时，我就思考传递能有什么方式？首先想到的就是奥运火炬的传递，但深入思考发现如果要做第三人称的Demo，这个并不好实现与怪物之间的交互和战斗。联想到最近游玩的游戏（详细可见文档第四章），决定以攻击机关作为切入点，再因为制作 Demo 的时间并不充裕，于是最终决定以能量球的形式来激活攻击机关。以玩家收集能量，传递给攻击机关，攻击机关再传递给怪物的游戏玩法作为 Demo 制作的方向。
  - 一开始就决定制作两个阶段的怪物，但如果怪物和角色技能没有变化的话，将略显无趣，于是在制作第二阶段时，我就在思考创新，再联想到之前游玩的游戏（详细可见文档第四章），给玩家设计了收集 5 格能量可以释放另一种形式的攻击的方式，也就是激光。以玩家在二阶段收集能量，不用再必须传递给攻击机关也能将能量传递给怪物作为第二阶段的制作重点。
- **关于“循环”**：
  - 我考虑过，该怎么让游戏尽量变得有趣，不至于特别无聊，也不至于过于简单。于是我为回能机关设计了 9s 产出一颗能量球的机制，为能量球设计了 6.5s 内不拾取就会消失的特性，为攻击机关设计了冷却机制，并且将玩家的 A 平台拆分成了三个子平台，使每个子平台之间留有空隙，玩家不得不跳跃进行转换平台，也更体现出跳跃功能不只是摆设。并且玩家处决可以获得1格能量，一定程度上鼓励玩家主动前往怪物的近处。
- **关于“博弈”**：
  - 能量是整个玩法的核心资源。面对 Boss 猛烈的攻击，玩家需要抉择是将 1 格能量传递给攻击机关进行常规消耗战，还是攒 3 格传递给攻击机关进行更强的攻击使 Boss 瘫痪，还是攒 5 格自己使用。我认为这种抉择能为战斗提供策略的深度。

## 四、 参考游戏拆解

+ **参考对象：《鸣潮》3.6 主线决战剧情（核心玩法）**
  - **拆解**：参考了战斗中“远程炮击破坏目标结构 → 后跨越地形攻击核心”的循环。本 Demo 借用了这个设计，让玩家在平台 A 攒满 3 格能量操控攻击机关攻击 Boss，使 Boss 瘫痪，随后生成平台 C 供玩家跳跃至 Boss 平台进行近战处决。

+ **参考对象：《原神》特瓦林副本战斗（战斗平台）**
  - **拆解**：参考了多平台分割的场地设计。本 Demo 构建了平台 A（拆分为3块子平台） 与平台 B，配合临时生成的平台 C，并设计了被 Boss 击飞或击退后“坠落深渊（Z轴 -1500 判负）”的惩罚。

+ **参考对象：《鬼泣5》 - 维吉尔（二段跳）**
  - **拆解**：参考了维吉尔的二段跳设计。本 Demo 的二段跳服务于玩家在A平台的三块来回跳跃躲避Boss攻击，还用于跨越 A→C→B 的断裂地形，提高玩家的容错率和手感。

+ **参考对象：《崩坏：星穹铁道》- 白厄（天降陨石）**
  - **拆解**：参考了白厄大招“从天而降的巨大陨石”的表现。本 Demo 将其转化为 Boss 的一个逼迫玩家走位的技能，配合预警圈和延迟砸地以及 CameraShake，来强化陨石的质量和压迫感。

+ **参考对象：《异环》（无首铁驭 Boss 战）**
  - **拆解**：参考了无首铁驭转阶段时的多段冲刺机制。本 Demo 根据实际将其抽象为“5 线并发直线冲刺方块”，通过数学公式每次攻击强制生成一条玩家所在的线，其它四条则随机，有可能会出现五条齐发，此时考验玩家能否运用闪避的 0.5s 的无敌安全抵御本次攻击。

+ **参考对象：《荒野大镖客：救赎 2》（死神之眼）**
  - **拆解**：参考了死神之眼的“子弹时间+屏幕滤镜”的设计。二阶段为玩家解锁新技能后在能量 5 格时，玩家按下 Q 键，全局时间减速至 0.2x，UI 叠加灰色滤镜，让玩家进入专属空间，制造掌控感，降低压力。

+ **参考对象：《明日方舟：终末地》（诀的二段大招）**
  - **拆解**：参考了诀二段大招的技能表现。在死神之眼的时间内，按鼠标左键消耗 5 格能量可以射出高伤激光，利用 Niagara 粒子系统的自带素材实现光束特效，作为二阶段的强有力表现的输出。
+ **参考对象：《崩坏：星穹铁道》（翁法洛斯后期剧情的计算机终端输出的风格和如我所书界面风格）**
  -  **拆解**：参考了翁法洛斯后期剧情揭示本质为计算机系统和如我所书的界面的表现。将原本的文字说明统一为计算机终端风格的文字说明，提高玩家代入感，降低 Demo 的简陋感。


## 五、 未实现设计的玩法建模与数据结构

+ **搁置空中冲刺（Air Dash）**
  + **设计目的**：
    + 原意是让玩家在 A 平台的三个子平台间拥有更主动的空中调整能力，增加躲避 Boss 攻击的容错率。

  + **技术取舍**：
    + 实测发现，在 UE 物理引擎中叠加空中位移，会导致玩家冲刺距离严重超出预期。尝试过修改摩擦力和对其进行速度限制，均失败。因此为了避免破坏游戏节奏，决定封闭此功能，仅保留地面冲刺。
  
  + **玩法建模与数据结构**：
    + 将空中冲刺设计为独立的 Gameplay Ability（`GA_AirDash`），激活前检查角色是否处于空中、是否处于死亡、眩晕或其他禁止移动的状态。满足条件后，让玩家朝摄像头的朝向方向冲刺。
    + 冲刺过程中使用 GameplayTag（`State.AirDashing`）标记角色状态，再通过预设的冲刺速度与持续时间来控制移动距离。冲刺结束后恢复正常移动状态。角色落地时重置空中冲刺次数。
  
+ **搁置完美闪避机制（Perfect Dodge）**
  + **设计目的**：
    + 为游戏提供高风险高回报的正反馈。

  + **技术取舍**：
    + 玩家胶囊体与 Boss 两个攻击技能的判定奇怪，尝试过为 Boss 的各个攻击的实际建模添加专门用于检测的 Box Collision，但判定依旧奇怪，触发依旧过于苛刻，故决定封闭此功能，将闪避的正反馈只保留 0.5s 无敌，掉落能量球的机制移于处决。

  + **玩法建模与数据结构**：
    + 在 Boss 攻击动画中添加 `AnimNotifyState` 标记攻击判定的时间窗口。给 Boss 攻击添加专用的大型 Box Collision 用于检测玩家是否在范围内。当玩家处于闪避状态且拥有 `State.Invincible` 的 Tag 时，判定为完美闪避。为防止同一次攻击多次触发，通过在 `AnimNotifyState` 的 Begin 时重置局部变量来防重。

+ **搁置二阶段平台碎裂与掉落**
  + **设计目的**：
    + 为二阶段的高空战斗增加环境压迫感，逼迫玩家不断转移阵地。

  + **技术取舍**：
    + 为了实现这个功能，我将原有的3块的整的A平台拆成 3*4 块平台，尝试在关卡蓝图中进行随机控制，但测试过程中出现很奇怪的物理效果，启用本功能后，平台未能按预期掉落，会出现建模在而碰撞体消失的 Bug，故决定封闭此功能。

  + **玩法建模与数据结构**：
    + 新建 `UPlatformManagerComponent` 挂载于 GameMode。在 `BeginPlay` 时用 `GetAllActorsOfClass` 将所有平台存入 `TArray<ABP_Platform*>` 数组。进入二阶段后，通过 `FTimerHandle` 每 2 秒随机 `Pop` 出一个平台，调用其 `StartFall()` 接口。再关闭 Collision 并开启 `Simulate Physics`。

+ **废弃跨关卡切图方案（Open Level）**
  + **设计目的**：
    + 原意是在 Boss 转阶段时通过切图营造宏大的转场。

  + **技术取舍**：
    + 本欲在 Boss 二阶段转换时，将二者同时震响高空切入新关卡，但在跨关卡时，我目前掌握的技术未能让 GAS 架构下的属性继承至新关卡。虽尝试过使用 GameInstance 传值，先扣除所有血量再通过 GE 加回去，但因为时机不对，导致血量清零时直接判定失败。故决定封闭此功能。

  + **玩法建模与数据结构**：
    + 在切图前，将 Player 的 ASC 数值写入 `GameInstance` 的 `FPlayerSaveData` 结构体。新关卡 `BeginPlay` 时，利用 `Make Outgoing Spec` 生成带有 `Set By Caller` 的 GE，直接将 GE 应用给新关卡的玩家，并延迟绑定 UI 委托确保血条刷新。

## 六、提高 Demo 完整度的设计及影响

本部分记录了我为提升 Demo 完整度所做的进一步设计构想，以及若实装这些功能，会对 Demo 体验产生的预期影响。

+ **攻击机关的调整**：
  + **设计**：将原本固定朝向 Boss 的攻击机关，改为需要玩家靠近后手动转动瞄准（例如通过鼠标控制机关底座旋转），对准 Boss 后才能激活发射。
  + **影响**：玩家转动校准期间会暴露在 Boss 的攻击下，增加了操作风险与策略深度；同时，亲手操控机关能增强玩家的代入感与交互感。

+ **背景环境**
  + **设计**：改变天空盒与背景氛围，一阶段为绿色的代码乱流，二阶段转场后突变为红色的代码乱流。
  
  + **影响**：通过背景的视觉反差，能提高 Boss 的压迫感。
  
+ **UI 界面**
  + **设计**：目前 UI 仅替换了文字与基础颜色。进一步的构想是将血条、能量槽的底框替换为类似“终端”的 UI 组件。
  + **影响**：契合了游戏背景设定，提升 Demo 的整体质感，提高代入感。
  
+ **打击感与受击音效**
  + **设计**：Demo 虽然已经有 CameraShake ，但还要添加Boss受到各种类型攻击的反应变化和相应的受击音效。
  + **影响**：解决几何体建模出戏的问题。且能进一步提升真实感，增强玩家操作的爽感与命中确认感。
